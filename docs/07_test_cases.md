## 3. 需要订书机确认的口径问题

这些是计划书、交接单与规则文档之间的措辞差异，会直接影响「预期」怎么写。在统一之前，本清单一律按 `01_game_rules_v1.md` 判断，避免把正确实现误报为 bug。

| 编号 | 冲突点 | 两边说法 |
| --- | --- | --- |
| GAP-01 | 女巫自救的表述 | 计划书 3.1「女巫每晚可以自救」 vs 规则 WITCH-001「解药整局只能使用一次」。正确预期应是「可以救自己，但整局一次」 |
| GAP-02 | 猎人开枪条件 | 计划书 3.1「被狼人杀死或投票出局时可以开枪」 vs 规则 4.2「夜间被狼杀**且未被救**才可开枪，**被毒不可**」。计划书漏了两个限定 |
| GAP-03 | 遗言范围 | 交接单「每名出局玩家最多 30 字遗言」 vs 规则表 7「第 2 天及以后夜间死亡**无遗言**」 |
| GAP-04 | 十二人局没有规则文档 | 计划书 3.2 已写狼王自爆可开枪；`01_game_rules_v1.md` 只覆盖九人局；守卫与解药同时作用于同一目标的结算顺序写的是「按团队约定」= 尚未定义。11/06 做十二人实验前需补 |
| GAP-08 | `create_game` 的真人数量校验过宽 | **已解决**：允许 `human_count=0`（仅 AI-only 训练）或 1 至 3（用户九人局），4 至 9 一律拒绝；已新增两项回归测试 |

## 5. 执行与记录方式

自动化测试：

```powershell
python -m unittest discover -s tests -v
```

手工验收的每次执行结果，按 `docs/05_competition_evidence_checklist.md` 第 8 节的格式，记录到：

```text
docs/evidence/YYYY-MM-DD_里程碑名称.md
```

记录必须包含：对应 commit hash、完成日期、测试命令、通过数量、已知问题和下一里程碑。**测试记录必须绑定明确的 commit**，否则无法作为比赛证据。
