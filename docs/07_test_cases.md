## 3. 口径问题（2026-10-23 已由订书机确认）

以下差异在 2026-10-23 由订书机确认处理口径：**一律以 `01_game_rules_v1.md` 的明细为准**，计划书与交接单的简写不作为判断依据。测试执行时按「确认口径」一栏写预期，避免把正确实现误报为 bug。

| 编号 | 冲突点 | 两边说法 | 确认口径 |
| --- | --- | --- | --- |
| GAP-01 | 女巫自救的表述 | 计划书 3.1「女巫每晚可以自救」 vs 规则 WITCH-001「解药整局只能使用一次」 | 可以救自己，但**解药整局只有一次**。TC-05 按此执行 |
| GAP-02 | 猎人开枪条件 | 计划书 3.1「被狼人杀死或投票出局时可以开枪」 vs 规则 4.2 | 按规则 4.2：夜间被狼杀**且未被救**才可开枪，**被毒不可**；白天放逐后遗言再开枪 |
| GAP-03 | 遗言范围 | 交接单「每名出局玩家最多 30 字遗言」 vs 规则表第 7 章 | 按规则表第 7 章：第 2 天及以后夜间死亡**无遗言**；投票放逐与白天猎人开枪保留遗言。**2026-10-24 变更**：遗言上限改为 **100 个汉字**，标点、数字与表情不计入汉字数 |
| GAP-04 | 十二人局规则缺口 | 计划书 3.2 写狼王自爆可开枪；规则文档只覆盖九人局 | 十二人局**暂不进入九人主链**；守卫与解药重叠的结算规则在 **11 月 2 日前定案**，定案前不做十二人验收 |
| GAP-08 | `create_game` 的真人数量校验过宽 | 代码原接受 `human_count` 0 至 9 | **已解决**：允许 `human_count=0`（仅 AI-only 训练）或 1 至 3（用户九人局），4 至 9 一律拒绝；已新增两项回归测试 |

另有两条被纳入固定回归范围，每次发版都要跑：

- **死亡原因可见性**：玩家不可见、观战者可见（规则 2.1）。对应 TC-09 与 GT-11。
- **观战密码不可复用固定值**（VIEW-004）。对应 TC-09 与 GT-12。

## 5. 执行与记录方式

自动化测试：

```powershell
python -m unittest discover -s tests -v
```

手工验收的每次执行结果，按 `docs/05_competition_evidence_checklist.md` 第 8 节的格式，记录到：

```text
docs/evidence/YYYY-MM-DD_里程碑名称.md
```

记录必须包含：对应 commit hash、完成日期、测试命令、通过数量、已知问题和下一里程碑。**测试记录必须绑定明确的 commit**，否则无法作为比赛证据。
