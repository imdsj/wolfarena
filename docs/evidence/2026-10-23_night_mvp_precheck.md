## P1 狼队长死亡后重选（WOLF-006）—— 高

复现步骤：

1. 构造一局，狼队长为 `p2`
2. 首夜狼刀预言家，女巫用毒药毒死 `p2`（队长）
3. `resolve_night` 后阶段进入 `DAY_ANNOUNCEMENT`
4. 白天流程尚未实现，为进入第二夜，将阶段直接置为 `VOTE` 后调用 `start_night`

实测结果：

```text
[第二夜 wolf_captain_id] p2
[该队长是否存活] False
[发言 r1 p1] 被拒绝：当前没有存活的狼队队长
[用死者队长提交刀人] 被拒绝：只有存活狼人可以提交狼刀
[第二夜重新选举（无参调用）] 成功，新队长 p3
[手动指定存活狼人为队长] 被拒绝：存活狼队长已经存在
```

判断：

- `elect_wolf_captain(state)` 无参调用可以重新选出存活队长，**能力存在**。
- 但没有任何环节自动触发它。`start_night` 不检查队长是否存活，`record_wolf_speech` 才发现「没有存活的狼队队长」并拒绝。
- 后果：如果白天流程实现后没有主动调用重选，**第一夜毒死队长的局会在第二夜彻底卡死**，既不能发言也不能刀人，游戏无法继续。

建议：把「队长死亡则重新选举」做成 `start_night` 的前置动作，或在白天流程末尾统一处理。规则 WOLF-006 的原文是「剩余存活狼人必须在下一夜开始前按 WOLF-001 至 WOLF-005 重新确定队长」，放在 `start_night` 入口处最不容易漏。

补充：`elect_wolf_captain` 在已有存活队长时会拒绝手动指定（「存活狼队长已经存在」），这条行为本身合理，但意味着**重选必须发生在队长死亡且新队长尚未产生的那一刻**，调用顺序要求较严，建议加一条集成测试固定这个顺序。

## P2 女巫当夜死亡仍生效（WITCH-010）—— 通过

步骤：狼刀女巫，女巫不使用解药，改用毒药毒一名村民，`resolve_night` 结算。

结果：

```text
[女巫是否死亡] True
[被毒村民是否死亡] True
```

符合 WITCH-010「女巫的药在夜间统一结算，女巫当夜死亡不会撤销已经提交的有效行动」。此项**通过**，建议保留为固定回归项。

## P3 同夜双药的拒绝方式（WITCH-002）—— 低

步骤：女巫先提交 `antidote`（救自己），紧接着提交 `poison`。

结果：

```text
[第二次提交毒药] 被拒绝：当前阶段不能提交女巫行动：NIGHT_RESOLUTION
```

判断：

- 结果上符合 WITCH-002（同一晚只生效一种药），因为女巫提交一次后阶段立即推进到 `NIGHT_RESOLUTION`。
- 拒绝理由是「阶段不对」，不是「同夜不能双药」。这在行为上没问题，但如果后续调整阶段推进时机，双药就可能漏拦。
- 建议：或保留现状但在测试注释里写明「双药由阶段推进保证」，或增加一条显式的「本夜已提交过药」校验，让规则与代码一一对应。

## P4 超时兜底未实现（WOLF-011）—— 中

检索 `backend/game_engine.py` 的公开函数，没有任何与超时、截止时间、自动跳过相关的接口：

```text
[超时/自动跳过相关函数] 无（未实现）
```

影响：

- 真人玩家不操作时，游戏会永久停在该阶段。规则 WOLF-011 要求「狼队长超时未提交决定时，本次行动按空刀处理」，夜晚顺序第 4 步也要求预言家超时为「未查验」。
- 项目目标是**一局约 5 分钟**，没有超时兜底就无法保证单局时长，也无法防止真人挂机。

建议：在白天流程实现的同时定义统一的超时策略——每个需要真人提交的阶段有一个截止时间，超时按规则默认值推进（空刀、未查验、不使用药、弃权）。这条不必今晚做，但属于 10/30 预成果验收的前提。

## 给联调的三条建议

1. **先验 P1**：构造队长在第一夜死亡的局，看第二夜能否正常发言和刀人。这是最容易漏且后果最严重的路径。
2. **确认 P3 的处理方式**：双药靠阶段推进拦截，是否接受这个实现方式，需要明确写进规则说明，否则以后改动阶段顺序会悄悄破坏它。
3. **给 P4 排期**：不需要今晚做完，但要在 10/26 前后定下超时策略，否则「一局 5 分钟」没有保障。
