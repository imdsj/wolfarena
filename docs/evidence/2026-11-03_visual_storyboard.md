# 3 分钟产品演示分镜稿 · 2026-11-03

本稿只写镜头与证据，不涉及代码改动。

## 录制前准备

1. 本地起服务：`python -m uvicorn backend.api:app --host 127.0.0.1 --port 8000`，
   用 `http://127.0.0.1:8000/` 录制，避免公网抖动。
2. 浏览器缩放 100%，窗口 1280×800；需要手机镜头时另开 390×844 窗口。
3. 提前创建好房间，确认本局真人被分到**村民**，这样才能拍到完整的夜晚阶段推进。
4. 录制前关闭微信、QQ、IDE 聊天，终端里不要露出 `.env` 内容。
5. 同一个 seed 只录一次完整流程；重录换 seed，避免时间线对不上。

## 分镜

### 镜头 1 · 开场 0:00–0:15

**画面**：产品首页标题「WolfArena / 九人局入口」，下方九人席位示意或大厅。

**旁白要点**：九人狼人杀 Web 平台，真人与 AI 混合对局，服务器权威判定，
按玩家视角隔离信息。

**证据来源**：真实页面 `http://127.0.0.1:8000/`；`README.md` 项目定位段。

**不要做**：不要用参考视频的片头、音乐、角色立绘。

### 镜头 2 · 大厅与建房 0:15–0:40

**画面**：输入昵称 → 点「创建房间」→ 房间页显示房间号、「复制房间号」、
观战密码、九人席位（1 真人 + 8 AI）。

**旁白要点**：一名真人即可开局，其余座位由 AI 补位；房间号和观战密码
都由服务端生成。

**证据来源**：真实页面录屏；`deploy/smoke.py` 中 `create_room: ok status=201` 的输出。

**不要做**：不要露出真实手机号、内网地址；不要把观战密码读到镜头正中。

### 镜头 3 · 夜晚 0:40–1:30

**画面**：点开局后，页面进入深色夜晚模式；顶部阶段标签依次出现
「首夜狼队讨论 → 狼队选择目标 → 预言家查验 → 女巫行动 → 夜间结算 → 天亮公告」，
每段可见「夜间推进」倒计时；下方事件流滚动。

**旁白要点**：夜晚按阶段逐个推进并带倒计时，非夜晚角色也能看到进度；
具体刀口、查验结果、用药仍按视角隔离，不会泄露给村民。

**证据来源**：`frontend/src/styles.css` 的 `body.night-mode` 主题；
`backend/ai_controller.py` 的 `phase_pace` 截止时间；
`docs/evidence/2026-10-30_night_phase_visibility.md`。

**不要做**：不要把这套说明成“AI 自己乱动”——要说明是服务端定时器在推进。

### 镜头 4 · 白天 1:30–2:20

**画面**：白天发言输入框与「提交公开发言」→ 投票下拉与「提交投票」→
结算页（胜方 + 九人身份）；可切一个观战窗口做左右对比。

**旁白要点**：玩家视角只能看到自己有权的信息；观战密码是独立入口；
真人闲置 20 秒会由系统代打，避免卡死。

**证据来源**：真实页面；`docs/evidence/browser-2026-10-26/390-player-in-progress.jpg`
与 `390-spectator-end.jpg`；`2026-10-30_human_idle_timeout_fix.md`。

**不要做**：不要把观战视角和玩家视角剪在一起不标注，会让评委误以为身份泄露。

### 镜头 5 · 训练 2:20–3:20

**画面**：终端依次执行三条命令，露出 `train-demo-20` / `eval-demo-20` 目录与
`matches_summary: true`；随后切到好人胜率表。

```powershell
python -m backend.simulator --games 20 --seed-start 2000 --policy l2 `
  --out training_runs/train-demo-20 `
  --model-out training_runs/train-demo-20/model.json --commit 71d2854
python -m backend.simulator --games 20 --seed-start 3000 --policy l2 `
  --model-in training_runs/train-demo-20/model.json `
  --out training_runs/eval-demo-20 --commit 71d2854
python -m backend.metrics --run training_runs/eval-demo-20
```

**表**：L0 84.0%、L1 36.5%、L2 v1 31.5%、L2 v2 35.0%（seed 1000–1199，各 200 局）。

**旁白要点**：20 局只证明训练管线能跑；正式对照是 1000 局训练 + 200 局评估；
L2 没有超过 L1，结论是 No-Go，负结果如实保留。

**证据来源**：`docs/evidence/2026-11-01_training_display_report.md`；
`2026-10-29_l0-200_manifest.json`、`2026-10-29_l1-200_manifest.json`、
`2026-10-29_l2-200_manifest.json`、`2026-10-29_l2-v2-200_manifest.json`。

**不要做**：不要说“训练后变强”“胜率提升”；不要用 20 局演示的胜负当结论。

### 镜头 6 · 收束 3:20–3:50

**画面**：终端 `Ran 234 tests ... OK`；公网地址
`http://106.14.113.216:8080/`；仓库地址 `https://github.com/imdsj/wolfarena`。

**旁白要点**：九人局闭环可玩、234 项自动化测试通过、公网可访问；
训练管线真实可复现，结论为负结果；不宣称 AI 变强。

**证据来源**：`2026-11-02_final_regression.md`；
`2026-11-02_defense_rehearsal.md`。

**不要做**：不要在结尾补一句“后续会变强”作为承诺。

## 边界

- 不复制参考视频的角色、剧情、音乐、画面素材；只借鉴“座位图 + 阶段 HUD +
  事件流”的信息组织思路。
- 所有出现的页面、终端输出、数字都必须来自真实运行，不用效果图或拼接素材。
- 全程不出现 API Key、服务器密码、后台地址、手机号、聊天窗口。
- 训练部分的唯一结论是“管线跑通、结果 No-Go”，不得表述为提升。
