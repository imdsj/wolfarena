# 逻辑漏洞审计与狼队执行一致性（2026-11-09）

## 一、问题来自一场真人对局

截图中的四个问题：

1. 狼人 9 号在 3 号还没发言时就说“3 号才是真预言家”，好人一眼看出信息差。
2. 2 号 AI 没有抓住这个漏洞，反而去质疑点破漏洞的 1 号。
3. AI 对明显的逻辑矛盾不敏感。
4. 狼队频道已经说“刀 5 号不改”，实战刀口与口头计划是否一致无法验证。

前三个是同一个根因：**发言解析只提取“谁怀疑谁”，没有检查“谁说了自己不可能知道的话”。**
第四个在 `39aadf8` 已有 `_wolf_agreed_target`，但缺少回归测试，且解析只认“刀N号”。

## 二、本次改动

### 1. 新增确定性逻辑审计

`backend/logic_audit.py`：

- `impossible_identity`：某人在目标尚未公开发言时，断言对方是预言家/女巫/猎人。
- `role_flip`：同一人先后自称两个不同神职。
- `top_suspect`：按证据权重排序，作为投票优先目标。
- `strongest_finding`：给模板发言和 LLM 提示词提供可引用的攻击点。
- `asserts_unspoken_identity`：生成后校验，拦住“未发言就定性”的句子。

为避免误伤，疑问句（“3号是预言家吗”）、假设句（“如果3号是预言家”）、
弱化表达（“我认/觉得/可能”）和否定句不计入。

LLM 已经生成一段正常发言、但完全没有提到这个漏洞时，`AIController` 会在
句首补一句确定性的抓漏洞结论（最多 140 字），保证演示时不会“模型刚好漏看”。

### 2. 投票策略接入

`backend/ai_growth.py` 的 L1 投票优先级调整为：

```text
明确自报预言家的查杀 > 逻辑漏洞嫌疑人 > 公开被怀疑最多的人 > 随机
```

没有自报预言家的“N号是狼”只算怀疑，不再被当成查验。

### 3. 发言提示词与生成校验

`backend/speech_composer.py`：

- 提示词新增“逻辑审计”块，直接列出可用的漏洞。
- 好人被告知：抓到“未发言就定性”要当场点破。
- 狼人被告知：绝不能替未发言玩家认神职。
- 模型仍写出违规句子时，整段丢弃，回退到确定性模板。

### 4. 狼队执行一致性

`_wolf_agreed_target` 的解析扩展为：

```text
刀5号 / 杀5 / 集火5号 / 刀口在5号 / 5号是刀口
```

并跳过“不刀5号”“别刀5号”这类否定表达。新增回归测试，使用截图原句验证
队长会执行“刀5号不改”。

### 5. 策略库新增四条种子

| strategy_id | 作用 |
| --- | --- |
| `good.catch-impossible-identity` | 抓未发言就定性的信息差并归票 |
| `wolf.no-unspoken-identity` | 狼人不得替未发言队友认神职 |
| `wolf.follow-agreed-kill` | 夜间频道定下的刀口必须执行 |
| `good.seer-report-needs-claim` | 未经自报的“查验”只当怀疑 |

四条均为 `rule_derived`、`samples=0`，没有填写胜率；后续仍需固定 seed
对照和人工审核才能晋升到 `validated/`。

## 三、验证

```text
python -m unittest discover -s tests
Ran 329 tests in 22.526s
OK
```

新增 `tests/test_logic_audit.py` 18 项，覆盖：

- 未发言就定性会被抓到；
- 目标已发言、疑问句、假设句不会误报；
- 两次自报不同神职会被抓到；
- 投票优先投逻辑漏洞嫌疑人；
- 模板发言会点破漏洞；
- LLM 漏看时会在句首补上抓漏洞结论；
- 狼人不会跟着复述这个结论；
- 狼队长执行频道约定的刀口；
- “刀口在N号”也能解析；
- 普通玩家的“N号是狼”不再被当成查验；
- 生成后校验能拦住违规句。
- 把活着的玩家说成已出局会被抓到并拦截；
- 刚说某人是金水、又要票他，会被判为自相矛盾；
- 真预言家的投票目标不会包含自己验出的金水。

2 局 L1 冒烟：

```text
completed_games = 2 / 2

action_legal_rate = 1.0
failed_games = 0
```

## 四、边界

- 审计是**模式匹配**，不是语义理解；同义改写（“三号那张牌是预言家”）目前抓不到。
- 它只解决“可判定的硬矛盾”，不替代 LLM 的局势推理。
- 狼队执行一致性只覆盖“频道里明确写出的刀口”；没有写数字的计划仍会走启发式。
- 本次没有重跑 200 局基准，不能据此宣称胜率变化。

## 五、同日晚第二场复盘

第二场暴露的是“场上事实”和“规则推理”，不是信息差：

1. AI 把仍然存活的玩家说成已经出局。
2. AI 不理解女巫自救可以解释平安夜，反而追问“救了谁”。
3. AI 作为预言家，刚报某人是金水，又主张票这个人。
4. AI 不理解一夜死两人通常是一刀一毒。

对应处理：

- 新增 `living_dead_claim`：发言把存活玩家说成出局，权重 3；
  LLM 生成后命中则整段丢弃。
- 新增 `report_vs_vote`：同一段发言里把某座位报成金水/好人，又主张票他，
  权重 3；LLM 生成后命中则整段丢弃。
- 真预言家的投票目标强制排除自己验出的金水，避免“自我否定查验”。
- 规则手册补充三条：女巫自救可以解释平安夜；一夜两人通常一刀一毒；
  真预言家不能投自己的金水。
- 发言解析补充“票1”“投1”“9金水”这类省略“号”的写法。

这一轮仍属于确定性校验：能拦住具体的硬错误，但不能保证模型理解所有局势。
