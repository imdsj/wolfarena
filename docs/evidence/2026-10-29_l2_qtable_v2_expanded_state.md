## 与 v1 的区别

v1 状态只有 4 维：自身角色、阶段、天数组、公开存活人数。
v2 在全部为“玩家可见 / 自身可见”的前提下增加了 4 维：

| 新增维度 | 取值 | 可见性依据 |
| --- | --- | --- |
| 自身存活 | `me1` / `me0` | 玩家自己当然知道 |
| 当日已投公开票数 | `v0` / `v1-4` / `v5+` | 投票公开 |
| 当日已发言人数 | `s0` / `s1-4` / `s5+` | 发言顺序公开 |
| 女巫剩余药 | `w00/w01/w10/w11`，非女巫恒为 `w-` | 仅女巫自己的物品 |

新增维度**不读取任何其他玩家的隐藏身份**。有测试守护：
把其他玩家角色全部改成狼人，两种 schema 的状态键都不变。
旧 `l2.qtable.v1` 模型仍可按 schema 1 加载并逐字节复现。

L2 v2 比 L1 低 1.5 个百分点（3 局），差距在噪声范围，**没有超过 L1**，
不能宣称提升。两次评估动作流哈希一致 `625b44c7…d1877`，可复现；
`backend.metrics` 复算 `differences=[]`。

## 结论

扩状态让 v2 的评估表现（35.0%）比 v1（31.5%）更接近 L1，但样本仍只有
200 局、差距 3 局，不构成显著提升。**G-06 维持 No-Go。**

结论不变：状态离散 + 终局稀疏奖励 + 九人共享一张 Q 表，是当前架构的
结构性瓶颈；下一步应把“目标选择”也纳入学习，并引入中间奖励
（存活、猎人开枪、女巫用药），而不是继续在动作类型这一层扩维。
