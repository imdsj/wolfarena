# 11 月 2 日答辩预演：三个必答问题

所有数字来自 `seed 1000–1199` 的 200 局对照，可由 `backend.metrics` 复算。

## 问题一：训练是怎么做的？

一句话：**在真实规则引擎里做全 AI 自博弈，固定 seed、训练与评估分离、
每一步都留下可复算的日志。**

- 规则层：`backend/game_engine.py` 实现九人局夜间顺序、白天发言、投票、
  自爆、猎人开枪和胜负判定；所有动作都经过服务端合法动作校验。
- 策略层：L0 随机、L1 人工规则、L2 表格式 Q-learning。
- L2 的状态只用玩家可见信息：v1 为自身角色、阶段、天数组、存活人数；
  v2 增加自身存活、当日公开票数、当日发言数、女巫自己的药量。
- 动作只从 `legal_actions` 里选，目标/选项/发言仍由 L1 规则决定。
- 奖励只有终局胜负：己方胜 +1、负 −1，中间步 0。
- 训练：seed 0–999 共 1000 局，`epsilon 0.3→0.05`、`alpha 0.2`、`gamma 0.95`。
- 评估：seed 1000–1199 共 200 局，加载模型后 `freeze()`，epsilon 固定 0。
- 每个 manifest 记录 commit、seed 范围、完整命令、文件 SHA-256；
  指标由 `backend.metrics` 从原始 JSONL 独立复算。

## 问题二：为什么 L2 没变强？

一句话：**状态太离散、奖励太稀疏、只学动作类别，L2 没有超过规则基线。**

| 策略 | 好人胜率 |
| --- | ---: |
| L0 随机 | 84.0% |
| L1 人工规则 | 36.5% |
| L2 v1 | 31.5% |
| L2 v2 | 35.0% |

- L2 v1 只有 199 个状态，v2 也只有 489 个，无法表达发言内容、票型细节
  和怀疑度。
- 奖励只有终局胜负，中间步为 0，信号极稀疏。
- 九名 AI 共用一个 Q 表，角色差异只能靠自身角色维度部分区分。
- 训练与评估是不同 seed 段，规则对手在训练中同步变化，价值基线在漂移。
- v2 比 v1 高 3.5 个百分点，但仍低于 L1；200 局下 3–10 局的差距属于噪声，
  不能据此宣称提升。

**结论：G-06 维持 No-Go。**

## 问题三：为什么仍然可信？

一句话：**因为每一个数字都能从原始日志重新算出来，而且我们如实保留了负结果。**

- 可复现：同模型同 seed 两次评估，`actions.jsonl` 哈希完全一致。
- 可校验：模型文件带 `content_hash`，被改动会直接加载失败。
- 可审计：manifest 绑定 commit、seed 范围、命令和文件哈希；
  `backend.metrics` 输出 `matches_summary: true`、`differences: []`。
- 工程可信：234 项自动化测试全过；公网 `:8080` 冒烟
  `ALL CHECKS PASSED`；干净目录克隆后可安装、可构建、可启动。
- 口径可信：负结果照实写，没有把“跑通训练管线”说成“训练后变强”。

## 可能的追问

**“L0 好人 84%，是不是说明好人太强？”**
不是平衡性结论。L0 是随机策略，狼队不会配合，好人胜率高是随机行为的产物，
只能作为“无策略基线”。

**“L2 和 L1 只差 3 局，算不算持平？”**
200 局下这个差距落在噪声范围，既不能说变强，也不能说显著变弱；
只能说**没有证据表明 L2 更好**。

**“下一步怎么才能真的变强？”**
把目标选择纳入学习，引入中间奖励（存活、猎人开枪、女巫用药），
并把发言与票型编码进状态；这是后续工作，不是本次结论。
