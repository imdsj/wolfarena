## 1. 执行原则

主线顺序固定为：

**独立 Agent → 策略多样性 → 工具调用与可解释性 → 策略审批与自动训练 → RAG 增强 → 多模态 → 提交材料。**

不重写现有九人局规则引擎、观战、自对弈、策略库和逻辑审计。所有 AI 动作继续经过服务器合法动作目录和规则引擎校验。

当前基础：

- 完整九人局与真人/AI 混合对局。
- 上帝视角观战和赛后身份揭示。
- 自对弈、复盘、候选策略、200 局评测和晋升机制。
- 硬规则审计、票型分析和生成后安全检查。
- 局面感知词法 RAG 已接入发言提示词。
- 2026-11-13 后端回归为 355 项测试通过。

最终必须能够现场证明：

1. 九个 AI 是九个独立 Agent，而不是同一策略换角色提示词。
2. 四种人格会真实改变目标选择、发言和战术使用。
3. Agent 能规划、调用工具，并用事件证据解释决策。
4. RAG 有来源、有检索过程、有生成质量对照。
5. 用户和 AI 提出的战术能训练、评测、审批和回滚。
6. 观战与赛后能看懂 AI 为什么这样行动。
7. 多模态能力真实可用，不用普通图表冒充多模态 AI。
8. 全量测试、前端构建、视频、文档和在线提交全部完成。

## 2. 总体架构

每个 AI 座位对应一个 `PlayerAgent`，拥有：

- 独立人格与风险偏好。
- 独立公开记忆和私密记忆。
- 独立当前计划与怀疑对象。
- 独立策略检索结果。
- 独立工具调用与决策轨迹。

统一工作流：

```text
观察可见事件
→ 检索相关战术
→ 调用逻辑审计/票型分析工具
→ 形成短期计划
→ 生成候选发言或动作
→ 服务器校验合法性与信息安全
→ 规则引擎执行
→ 更新当前 Agent 记忆与决策轨迹
```

共享部分只包括：

- 游戏规则与胜负判定。
- 合法动作目录。
- 房间调度与事件广播。
- 只读工具实现。
- 策略库和模型配置。

模型不能修改游戏状态，不能执行任意代码，不能读取其他玩家的隐藏身份，也不能选择服务器未提供的目标。

页面展示的是结构化决策依据，不展示原始模型思维链。例如：

```text
3 号 · 逻辑型
当前目标：核实 5 号的查验链
逻辑依据：第 18、23 条发言相互矛盾
票型依据：2、5 号连续两天同票
命中战术：good.hard-rule-first
最终决策：优先质疑 5 号
```

## 4. 阶段二：每座位一个 Agent

### 4.1 建立独立 Agent

新增 `backend/player_agent.py`：

```python
class PlayerAgent:
    player_id: str
    persona: Persona
    policy: L1RulePolicy
    private_memory: AgentMemory
    public_memory: AgentMemory
    current_plan: AgentPlan | None
    decision_traces: list[DecisionTrace]
```

改造：

- `backend/rooms.py`：把单一 `ai_policy` 改为 `dict[player_id, PlayerAgent]`。
- `backend/ai_controller.py`：根据当前行动座位取得对应 Agent。
- `backend/speech_composer.py`：接收当前 Agent 的人格、记忆和检索结果。
- `backend/rooms.py`：每次动作完成后更新当前 Agent 的记忆。

`AIController` 只负责调度，不再作为九个 AI 共用的决策主体。

每个 Agent 只接收自己的 `ActionView` 和可见事件。私密记忆只保存该玩家合法可见的信息，例如自己的查验、药剂、狼队友和狼队讨论。

### 4.2 加入四种策略人格

新增 `backend/personas.py`：

| 人格 | 好人偏好 | 狼人偏好 |
| --- | --- | --- |
| 冲锋型 | 先手归票、敢定狼 | 悍跳、冲票、刀对跳 |
| 稳健型 | 跟强证据、避免分票 | 深水、跟票、刀暴露神职 |
| 逻辑型 | 硬矛盾、票型、查验链优先 | 倒钩、切割、抓发言漏洞 |
| 搅局型 | 逼发言、多目标施压 | 假动作、多线施压 |

实现 `ArchetypePolicy(L1RulePolicy)`，只重排服务器给出的合法目标，不另写一套游戏规则。

人格由 `seed + seat` 稳定分配；狼队强制互补，避免三个狼人全是同一人格。

### 4.3 页面显示人格

修改：

- `backend/schemas.py`：AI 座位增加 `archetype`。
- `frontend/src/types.ts`：同步类型。
- `frontend/src/components/RoomPanel.vue`：座位卡显示“逻辑型 AI”等标签。
- `frontend/src/components/GameResultPanel.vue`：赛后显示每位 AI 的人格和主要战术。

### 4.4 测试与验收

新增：

- `tests/test_player_agent.py`
- `tests/test_personas.py`

必须覆盖：

- 真人加入、死亡、观战和赛后流程不回归。

## 5. 阶段三：真正的 Agent 工具调用

### 5.1 定义三个工具

新增 `backend/agent_tools.py`：

```text
audit_logic
analyze_votes
search_tactics
```

工具由服务端绑定当前 `state + actor`，模型不能传入任意文件路径、其他玩家身份或 Python 代码。

统一返回结构化结果：

```json
{
  "evidence_event_ids": [18, 23],
  "findings": [],
  "tactic_ids": [],
  "summary": ""
}
```

### 5.2 实现有限工具循环

在 `backend/ai_provider.py` 增加 OpenAI 兼容 Function Calling：

```text
模型请求工具
→ 服务端执行白名单工具
→ 将结果返回模型
→ 模型生成最终候选决策
```

每次决策最多三轮工具调用。失败必须明确记录，使用规则策略降级时不能伪报 Agent 调用成功。

最终输出使用 Pydantic 校验：

```python
class AgentDecision:
    speech: str | None
    target_id: str | None
    choice: str | None
    rationale: str
    evidence_event_ids: list[int]
    tactic_ids: list[str]
```

`target_id` 和 `choice` 仍需经过现有合法动作目录校验。

### 5.3 保存决策轨迹

新增 `AI_DECISION_TRACE`，记录：

- 当前人格与短期目标。
- 调用了哪些工具。
- 引用了哪些公开事件。
- 命中了哪些战术。
- 最终动作及选择理由。
- 是否被服务器拒绝、是否使用降级策略。

可见性：

- 普通玩家对局中只能看自己的私密 Agent 信息。
- 观战者可见全部 Agent 决策轨迹。
- 赛后向所有玩家揭示完整轨迹。

### 验收

- 一次真实 API 对局中能看到模型主动调用工具。
- 工具结果与当前玩家可见信息一致。
- 模型无法通过工具参数读取任意文件或其他玩家隐藏身份。
- 工具失败和降级有明确记录。

## 6. 阶段四：持续强化发言与抓漏洞能力

### 6.1 逻辑审计规则

继续扩展 `backend/logic_audit.py`：

- 同一玩家前后自报不同身份。
- 预言家一晚多验、查验链与时间不符。
- 金水和查杀声明前后冲突。
- 嘴上说好人却投票给该玩家。
- 号召投票、击杀或查验已死亡玩家。
- 未发言就断言其神职身份。
- 发言归票与实际投票不一致。
- 狼人白天发言与狼队计划明显冲突，仅在合法视角用于内部调整。

每条结论必须关联原发言事件，不能只生成“某号可疑”。

### 6.2 发言生成约束

`backend/speech_composer.py` 的输出必须满足：

- 至少回应一条当前可见发言或公开事件。
- 有嫌疑对象时给出证据。
- 不重复上一轮发言。
- 不泄露未公开身份。
- 狼人发言与夜间计划一致。
- 遗言不再讨论下一轮行动。
- 生成的目标仍存活且动作合法。

新增 `tests/fixtures/speech_cases.json`，收集正确与错误案例；每次修改提示词都重跑整个语料集。

持续记录：

- 硬矛盾检出率与误报率。
- 非法动作数，目标为零。
- 信息泄露数，目标为零。
- 重复发言率。
- 模板降级率与模型超时率。

### 验收

- 每类漏洞至少有一个正例和一个反例。
- 相同输入重复运行时，规则审计结果确定。
- 生成后审计发现问题时不会把违规内容发布到事件中。

## 9. 阶段七：API Embedding 增强 RAG

保留局面感知词法检索作为可复现基线，新增 `backend/tactic_retrieval.py`。

配置：

```text
WOLFARENA_EMBEDDING_API_KEY
WOLFARENA_EMBEDDING_BASE_URL
WOLFARENA_EMBEDDING_MODEL
```

实现流程：

1. 对 `seeds/validated` 战术卡生成 embedding。
2. 缓存向量、模型版本和卡片内容哈希。
3. 当前局面先按角色、阶段过滤。
4. 结合词法分数和向量相似度排序。
5. 将战术编号、来源、触发条件和风险注入 Agent。
6. API 失败时明确标记为词法模式，不冒充向量命中。

制作至少 30 个固定局面，比较：

- 无 RAG。
- 词法 RAG。
- API 混合 RAG。

评估：

- Recall@3。
- 逻辑错误率。
- 证据引用率。
- 重复发言率。
- 人工发言质量评分。

结果保存到 `docs/evidence/rag_ablation.md`，用于回应评分表中的“生成质量是否因检索增强而显著提升”。
