## 5. 九人局规则

角色：

```text
3 狼人
3 村民
1 预言家
1 女巫
1 猎人
```

### 5.1 夜间顺序

1. 每名存活狼人第一轮内部发言。
2. 每名存活狼人第二轮内部发言。
3. 狼队长选择空刀、自刀或击杀存活玩家。
4. 预言家查验其他存活玩家。
5. 女巫选择不用药、解药或毒药。
6. 服务端统一结算。
7. 合格猎人决定是否开枪。
8. 检查胜负。
9. 未结束则天亮。

### 5.2 女巫

- 解药、毒药整局各一次。
- 同一晚只能使用一种。
- 解药能救任何人，包括自己和狼人。
- 用解药救非狼刀目标仍消耗解药。
- 有解药时，女巫知道当夜准确刀口。
- 狼人空刀时，女巫知道“没有刀口”。
- 解药消耗后，女巫即使还有毒药，也不能查看当夜刀口。
- 被毒猎人不能开枪。

上述规则已实现：

- 引擎函数 `get_witch_kill_target`。
- `RoomSnapshot.witch_kill_target_visible`。
- `RoomSnapshot.witch_kill_target_id`。
- Vue 私密信息卡。
- 有刀口、空刀、无解药、非女巫测试。

### 5.3 狼人

- 每名存活狼人每晚两轮私聊。
- 只有狼队长提交刀人。
- 可空刀、自刀、击杀存活玩家。
- 队长死亡后下一夜重新选择。
- 只有存活狼人能在白天讨论阶段自爆。
- 首名自爆公开身份、无遗言、取消当天投票。
- 自爆后最多 10 秒续爆窗口。

### 5.4 预言家

- 每晚查验一名其他存活玩家。
- 结果只有 `wolf` / `good`。
- 查验结果只对本预言家、观战者可见。

### 5.5 猎人

- 夜间被狼刀且未获救，可开枪。
- 被毒或同时狼刀加毒，不可开枪。
- 被投票放逐后先遗言，再决定是否开枪。
- 被猎人带走者先遗言，再继续下一阶段。

### 5.6 白天流程

1. 公布夜间死亡名单。
2. 第 1 天夜间死亡者按名单顺序遗言。
3. 第 2 天及以后夜间死亡者没有遗言。
4. 存活玩家按规则起点轮流公开发言。
5. 狼人可自爆。
6. 进入投票。
7. 截止投票后公布票型。
8. 唯一最高票放逐；平票或零票无人出局。
9. 被放逐者遗言。
10. 被放逐猎人可开枪。
11. 检查胜负。

公开和遗言各 30 秒；遗言最多 100 个汉字，标点、数字、表情不计。

### 5.7 投票

- 只有存活玩家能投票。
- 可以自投、弃权、改票。
- 截止后锁票。
- 未投票视为弃权。
- 唯一最高票放逐；平票无人出局。

当前网页行为：

- 房主可在未全员投票前手动截止。
- 所有存活玩家都投票后，服务端自动截止并结算。
- 这修复了此前投票后必须找房主按钮、容易误以为卡死的问题。

### 5.8 胜负

- 狼人全灭，好人胜。
- 存活狼人数大于或等于存活好人数，狼人胜。
- 两者同时满足时先判狼人全灭，所以好人胜。

### 5.9 身份可见性

- 普通玩家只看到自己身份。
- 存活狼人看到自己与狼队友。
- 死亡狼人失去狼队视角。
- 观战者游戏中可看全部。
- 游戏结束后所有人看到完整身份和死因。
- 死亡玩家刷新后仍是玩家视角，不升级为上帝视角。

## 8. L0、L1、训练版必须严格区分

```text

```


E 盘 `.git` 目录被 ACL 显式 DENY（`(DENY)(W,D,Rc,DC)`，作用于沙箱 SID），
即使授予目录写权限也无法写入元数据。因此本会话使用独立临时 Git 目录
（`--git-dir` + `--work-tree`）读取、提交和推送，仓库文件本身仍直接改在 E 盘。
远端和临时元数据已验证一致，但**本地 `.git` 的引用仍然落后**。普通 PowerShell 中
下一位 AI 应先：

```powershell
git fetch origin
git status --short --branch
git rev-parse HEAD
git rev-parse origin/main
```

若 `git rev-parse HEAD` 仍是 `222577c`，说明本地引用未同步；此时工作区与远端
内容一致，执行 `git reset --mixed origin/main` 即可对齐引用且不动文件。
先确认再同步，不要直接执行 reset --hard 或强推。
